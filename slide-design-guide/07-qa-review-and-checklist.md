# 07. 品質検査・独立レビュー・最終テスト

スライドは「作った本人」が見直すと、頭の中にある意図を無意識に補完してしまい、文字切れ・論理の飛び・意味不明な図に気づけません。  
機械的チェック → 独立レビュー（別スレッド／他者視点） → 人間の4つの最終テスト、の順で品質を担保します。

---

## 1. 横断的数値基準（配信前最低ライン）

複数の大学ガイドライン（Harvard Chan / ACU）、WCAG 2.x、学術・コンサル実務基準の合意値です。

| 項目 | 基準・下限 | 典拠・理由 |
|---|---|---|
| 本文フォント | **≥ 18pt**（推奨 20–24pt、絶対下限 16pt） | Harvard Chan / ACU / 投影可読性 |
| 見出しフォント | **≥ 24pt**（推奨 26–32pt） | Harvard Chan / ACU |
| 条件文・注記 | 解釈に必要な条件は **≥ 16pt**（純粋な出典・ページ番号のみ 11–14pt 許容） | 後ろの席からの検証可能性 |
| コントラスト比 | 本文 **≥ 4.5:1**、大きい文字・図表 **≥ 3:1** | WCAG 2.x AA 基準 |
| 1枚の箇条書き | **≤ 4項目**（連続テキストは最大2行目安） | Harvard Chan / ACU / TEDx |
| 使用色数 | 黒白を除き **≤ 3〜4色** | 60-30-10 / コンサル標準 / Ethos3 |
| 使用書体数 | **≤ 2書体**（＋数式用 Cambria Math） | McKinsey / ACU |
| 行間 | 欧文 **≥ 1.5**、日本語 **≥ 1.15** | Harvard Chan / 和文組版 |
| 進行ペース | **約1枚 / 分**（±30%） | Harvard Chan / Naegle (2021) |
| 1枚の要素数 | 口頭発表は **≤ ~6ブロック**（読む用・講義は領域グループ化＋1結論が必須） | Naegle (2021, *PLOS Comp Biol*) |

## 2. 視覚検査チェックリスト（3段階）

PDF やスライド画像に書き出した上で、以下の3パートを順に確認します。

### PART 1 — 機械的・構造的欠陥（見つけたら必ず修正）
- テキストボックスやスライド端からの文字はみ出し（Overflow）・見切れ
- 要素同士の重なり（文字が図形や線と被っている、ラベル同士の衝突）
- 余白不足（外周マージン < 0.4インチ、ブロック間ギャップ < 0.3インチ）
- グリッド・行/列のズレ（同じ役割のボックスの高さ・左端が不揃い）
- 低コントラスト（薄いグレー文字、背景写真・網掛けに埋もれた文字）
- テンプレートの消し忘れ（`XXX`, `未定`, 古い年号, 空のままのフレーム）
- 擬似リスト記号（手打ちの `"•"` `"1."`、独立した番号図形）
- 画像化・PDF変換での文字化け（豆腐 `□`、意図しない MS ゴシック化）

### PART 2 — デザインシステム＆構成準拠
- **コンタクトシート（一覧）検査**：サムネイル一覧で一貫したデザイン体系とバリエーション（3枚連続同一レイアウトがないこと）が見えるか。
- **タイトル位置と長さ**：コンテンツスライドのタイトルが上部固定帯にあり、原則1行の主張文になっているか。
- **1枚1主張＆1証明オブジェクト**：2つの話題が混ざっていないか。テキストだけの結果スライドになっていないか。
- **カバー構成**：表紙に不自然な巨大空白がなく、ハイライト色が意味なく乱用されていないか。
- **日本語の折り返し**：単語や手法名の途中で不自然に改行されていないか。ボックス幅が狭すぎて3行以上に折り返されていないか。
- **カードパディング対称性**：塗りボックス内の上下左右の余白が均等か。
- **制作メモの露出禁止**：`クリックで表示` `TODO` 等の制作指示がスライド面に出ていないか。
- **統一性**：キッカー、キャプション、ページ番号、フッターの位置とスタイルが途中で変わっていないか。

### PART 3 — アクセシビリティ・ジャンル固有ブロッカー
- **色のみへの依存**：赤緑や色分けだけで良否・系列を伝えていないか。
- **視線誘導順（Reading Order）**：パッと見て「タイトル → 主役の図・数値 → 解釈」の順に視線が動くか。
- **学術ブロッカー**：
  - 論文図の丸貼り（軸文字が小さすぎて読めない）
  - 軸ラベル・単位なし、誤差棒の種類（SD/SE/95%CI）と `n` の欠落
  - `jet / rainbow` カラーマップの使用
  - 引用図の `From ...` / `Adapted from ...` 欠落
  - 未定義の記号、結論の先送り（ミステリー構成）
- **ビジネスブロッカー**：
  - 結論後回し（Conclusion-last）
  - 行動しただけのタイトル（「Xを調査した」ではなく「Xがコストの20%を占める」）
  - 出典なしの数値、変曲点の説明がない急成長（ホッケースティック）曲線
  - 1枚に複数チャートが並ぶだけのダッシュボード投げ出し、不要な小数点（False precision）

## 3. 独立レビュー（Fresh-Eye Review）と採否表

作成したAIスレッドとは**別の新しいチャット／サブエージェント**に、制作経緯やプロンプトを一切伏せて成果物（PDF/画像）だけを渡し、以下の3軸で辛口レビューさせます。

1. **日本語・文体**：完了形と進行形の取り違え、不自然な名詞圧縮語、表記揺れ、AI特有の定型句。
2. **論理展開**：タイトル通し読みでの論理の飛び、前提と結論の逆転、左右カラム（「事実→解釈」）の不整合。
3. **破綻検査**：タイトルに書いた数（「3つの課題」）と本文項目数の不一致、根拠のない評価語（「十分な成果」）、出典欠落。

### 採否表（Decision Table）で判断する
AIレビュアーの指摘をすべて盲目的に直すのではなく、まず採否表で仕分けしてから修正に入ります（修正は原則1〜2サイクルで止め、無限微調整に陥らない）。

| # | ページ | 指摘内容（原文） | 種別 | 採否 | 対応・理由 |
|---|---|---|---|---|---|
| 1 | P.3 | 「精度帯に追いついた」は完了形で不自然 | 日本語 | 採用 | 「追いついている」に修正 |
| 2 | P.5 | 前提の表から右列の結論が導けていない | 論理 | 採用 | 右カラム見出しを結論の因果表現へ変更 |
| 3 | P.7 | 用語の定義がスライド上にない | 日本語 | 不採用 | P.2で定義済みの総称のため維持 |

## 4. 納品前の4つの最終テスト

1. **タイトル通し読みテスト**：本文を隠してタイトルだけ順番に読み、1本の筋の通った主張になっているか。
2. **3秒グランス（Glance）テスト**：サムネイルサイズで各スライドを3秒だけ見て、「主役は何か」「何が言いたいか」を言葉にできるか。
3. **50%ズームテスト / Back of the Room Test**：画面を50%縮小（またはモニター対角線インチ数と同じフィート距離だけ離れて）見て、文字・軸ラベル・注記が無理なく読めるか。ギリギリならフォントが小さい。
4. **グレースケールテスト**：画像を白黒変換（またはモノクロ表示）にしてみて、どの系列・どの強調も意味が失われないか。

## そのまま使える視覚QA・レビュー用プロンプト

PDFまたはスライド画像を別のAIセッション／サブエージェントに渡す際に使えます：

```text
添付したスライドPDF（または画像群）を、実際の聴衆・読者の目線で検査してください。
用途プロファイル：[進捗報告 / 論文紹介 / 学会講演 / コンサル読む資料 / 講義 / ポスター]
言語：[日本語 / 英語]

制作背景はあえて伏せています。1ピクセル単位の些細な好みではなく、実際の聴衆が気づく欠陥・論理の飛び・読みにくさをページ番号付きで指摘してください。問題がなければ「OK」と書いてください。

確認項目：
1. 機械的欠陥：文字はみ出し、重なり、余白不足、揃えズレ、コントラスト不足、テンプレ残骸、文字化け
2. デザイン・構造：3枚連続の同一レイアウト、AI臭（紫グラデ・均等カード・片側カラーバー・絵文字見出し）、トピックだけの無主張タイトル、図の根拠不足、日本語の不自然な単語途中改行、狭い箱による3行以上の折り返し
3. 視認性・アクセシビリティ：色だけで意味を伝えている箇所、小文字に隠された重要条件（N数・誤差棒定義・出典）、視線誘導の不明瞭さ
4. 論理・文章：タイトル通し読みでの論理飛躍、タイトルの数と中身の不一致、AI臭い回りくどい日本語

出力形式：
1. 致命的欠陥（Blocking defects：必ず直す）
2. 構成・UX上の主要リスク（Major risks）
3. 視認性・アクセシビリティ上の懸念（と画像だけでは検証できない限界）
4. 軽微なブラッシュアップ案（Minor polish）
5. 維持すべき良い点（Strengths）
```
