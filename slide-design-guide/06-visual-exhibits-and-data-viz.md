# 06. 図表・グラフ・ダイアグラム・数式・引用の設計規範

スライドの説得力を決める「証明オブジェクト（Visual Exhibits）」の作り方と、学術・実務における図表の厳格な作法です。

---

## 1. 5大作図手法の選び方（決定木）

図表の種類によって最適な作成手段が異なります。目的に合わない手法で描くと、後から直せない・文字が潰れる・座標がズレる事故が起きます。

```text
図版（Exhibit）の要件
 ├─ Q1. 発表直前まで人間が PowerPoint 実機で数値や項目を微修正するか？
 │    └─ YES → 【手法1: PowerPoint ネイティブ図形・チャート】
 ├─ Q2. 実験データ、散布図、誤差棒、連続関数、ヒートマップ、相図か？
 │    └─ YES → 【手法2: Python (matplotlib / seaborn) → 高解像度画像 / ベクター】
 ├─ Q3. フローチャート、状態遷移、シーケンス、因果関係などの論理構造図か？
 │    └─ YES → 【手法3: テキスト DSL (Mermaid / Typst CeTZ / PlantUML)】
 ├─ Q4. アイコン、幾何シンボル、単機能の装置線画、化学構造式か？
 │    └─ YES → 【手法4: ベクター SVG（テキストはパス化済み）】
 └─ Q5. 構成検討・プロトタイピング段階の矢羽・比較図か？
      └─ YES → 【手法5: HTML / CSS（構成確定後にネイティブ図形へ実装）】
```

### 各手法の実務ポイント
- **手法1（ネイティブ図形・チャート）**：単純な棒・折れ線・円・表は、後から編集しやすいよう可能な限りネイティブチャートにする。円グラフやゲージを四角形の連続配置で自作せず標準図形を使う。チャート内の軸・凡例フォントもスライド全体の書体に揃える。
- **手法2（Python スクリプト描画）**：
  - **「論文の図をコピペしない。スライド用に再描画（Re-plot）する」**。
  - **サイズ一致の原則**：`plt.subplots(figsize=(W, H))` の `(W, H)` を、スライド上に貼る実インチ数と一致させて出力（`dpi=200〜300`, `bbox_inches="tight"`）すると、図中フォントの pt がスライド本文と100%一致して歪みません。
  - 必ず作図スクリプトをスライドの横に保存し、再実行・修正できるようにします。
- **手法3（テキスト DSL）**：AI に座標を手計算させて箱と矢印を描かせると、重なりや線ズレ（座標ハルシネーション）が頻発します。フローや状態遷移は Mermaid や CeTZ 等のテキスト DSL で書かせてレンダリングする方が幾何学的に破綻しません。
- **手法4（ベクター SVG）**：SVG 内に `<text>` タグを残すと開いたPCのフォント環境で文字化け・位置ズレを起こします。テキストはすべてアウトライン化（Convert to Path）するか、300dpi以上の高解像度 PNG を併用します。

## 2. 科学・ビジネス共通のグラフ作法

### デフォルト出力（matplotlib / Excel 素出し）を禁止する
デフォルトのままのグラフは「下書き・未完成」に見えます。最低限以下を整えます。
1. **上と右の枠線（Spines）を消す**：`ax.spines[["top", "right"]].set_visible(False)`。
2. **グリッド線を薄くする**：主データより主張しない極薄のグレーにするか消す。
3. **線幅・マーカーを2〜3倍にする**：論文用（印刷300dpi）の細い線は、プロジェクター投影で消えます。
4. **図中フォントサイズ**：最終スライド上の表示スケールで軸ラベル・目盛り・注釈が **最低 12〜16pt 以上** になるよう設定する。
5. **直接ラベル付け（Direct Labeling）**：離れた凡例ボックスではなく、曲線や棒の近くに直接系列名を配置する。注釈・網掛け領域がデータ点や曲線を隠さないようにする。
6. **デッキの配色と統一**：フィット曲線＝構造色（深紺等）、主役データ＝ハイライト色（朱色等）、比較対照＝グレーのように、スライド全体のカラーロールと合わせる。
7. **主張の可視化**：タイトルが「非単調に極小を持つ」と言うなら、その極小点に矢印・丸印・注釈を付けて一瞥で視線が行くようにする。

### カラーマップと色覚多様性（最重要）
- **連続値には知覚均等カラーマップを使う**：**`viridis`, `plasma`, `inferno`, `magma`, `cividis`** を使用します。
- **`jet` / `rainbow` カラーマップの禁止**：明度変化が不規則なため、データに実在しない「偽の境界」を作り出したり、本物の微細な変化を隠したりします（グレースケール印刷でも破綻します）。
- **カテゴリカルデータには Okabe-Ito（Wong パレット）等**：赤緑の区別が困難な色覚特性（男性の約8%・女性の約0.5%）でも判別できる配色を選びます。

### 誤差棒・統計・グラフ種類の注意
- **誤差棒（Error bars）**：それが **SD（標準偏差）／ SE（標準誤差）／ 95% CI（95%信頼区間）** のどれであるかと、サンプル数 **`n`** を図中または直近の条件行に必ず明記します。SE のみのエラーバーは約67%信頼区間に過ぎず、群間差を過大に見せる誤解を招きやすいため、可能な限り 95%CI が推奨されます（Cumming et al., 2007）。
- **禁止グラフ**：3D棒グラフ・3D円グラフ（奥行き効果で数値比率が歪む）、レーダーチャート（面積の歪み）、意味のない二重軸（スケール操作）、Y軸の不適切な切り取り（差異の誇張：Lie Factor）。
- **ウォーターフォールチャート（差異分析）**：`START + DRIVERS = FINISH` で構成し、バー数は7〜10本を上限（小項目は「その他」にまとめる）。
- **複数パネル vs 逐次提示（Build）**：複数条件を横に並べて**比較**させたいときは1枚に同時提示し、ステップ1→2→3と**段階的な過程**を理解させたいときだけ逐次提示（ビルド）にします。マルチパネルには左上 `(a)(b)(c)` ラベルを統一配置します。

## 3. シミュレーション画像・動画の見せ方

- **必要な情報の明示**：シミュレーション画像や動画には必ず **スケールバー（空間尺度）** と **タイムスタンプ** を入れ、比較対象パネル間で **カラーマップとレンジを完全に同一** に揃えます。
- **事実と仮定の境界**：動画は「どこが実測・物理法則で、どこがモデルの仮定か」が曖昧になりやすいため、ラベルや矢印で注釈を入れます。
- **並べて比較するとき**：パネルのサイズとベースラインを揃え、単なるパラメータ値（`ρ=0.2` / `ρ=0.8`）だけでなく、比較の軸（`低密度` vs `高密度`、`対照群` vs `摂動`）と **「どこを見てほしいか」の1行 takeaway** を必ず書きます。
- 動画の決定的瞬間（転移点・極値）は静止画スナップショットも併置しておくと、口頭で振り返りやすくなります。

## 4. 数式の見せ方

- **導出のダンプ禁止**：一般講演や報告では、聴衆のほとんどは長い途中式を追えません。スライドに載せるのは **「主張を直接担うキーとなる式」＋「物理的・直感的意味」** に絞り、詳細な導出は Appendix へ移します。
- **記号定義の徹底**：式に登場するすべての記号・変数は、どんなに自明に見えても **初出時に式の直下または横で必ず定義** します（複雑な発表では冒頭に記号表スライドを置く）。
- **視覚との対応づけ**：式の各項を色分けして概念図や口頭説明の言葉とリンクさせると理解負荷が劇的に下がります。
- **表示サイズ**：ディスプレイ数式は **24〜28pt** がバランス良く読めます（1つの主役式だけなら最大32pt。ポスター並みに巨大化させない）。
- **段階導出のコツ**：数式を1行ずつ展開して見せる場合は、スライド間で式全体の横位置・ベースラインがガタつかないよう配置を揃えます。

## 5. 引用・他者図版のクレジット作法

- **「描き直せば著作権・引用表記が不要になる」は誤り**：他者の論文やWeb記事の図を再描画（Redraw）しても、元のアイデア・構成に対する出典明記は必須です。
- **表記の使い分け**：
  - そのまま転載：`From [著者名] ([年]), [出典]`
  - 一部改変・再描画：`Adapted from [著者名] ([年]), [出典]`
  - 許諾取得時：`Reproduced with permission from ...`
- クレジットは対象図の直下（11–12pt 以上で読めるサイズ）に配置します。先行研究紹介では単なる年代順リストではなく、「自分の研究・主張とどの軸で比較しているか」で整理し、各研究の横に `(Author, Year)` を添えます。
