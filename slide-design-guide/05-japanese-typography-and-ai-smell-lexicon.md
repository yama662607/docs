# 05. 日本語タイポグラフィ＆文章のAI臭ワード・構文排除集

日本語スライドが「素人っぽく見える」「AIが書いた文章だとすぐバレる」最大の原因は、**和文フォントのウェイト・改行・サイズ設計の不備**と、**AI特有の冗長で優等生的な言い回し（AI Slop）**にあります。

---

## 第1部：日本語タイポグラフィ・文字可読性の規約

### 1. フォント選びと環境互換の落とし穴
| 役割 | 推奨書体・ウェイト | サイズ目安 |
|---|---|---|
| 見出し（タイトル） | ゴシック体＋**太字（ウェイト明示）** | 24–28pt（強調時は32–44pt） |
| 本文 | ゴシック体（Regular / W3相当） | **18–20pt**（18pt以上推奨、16pt未満禁止） |
| 実験条件・注記 | 同上（投影で読む条件文） | 13–14pt（やむを得ない純粋な出典・ページ番号のみ 11–12pt） |
| 英字・数値 | **Arial / Helvetica Neue** 等（数字を和文フォントで組まない） | 本文に合わせる |
| 数式 | Cambria Math（PowerPoint標準OMMLの要件） | 本文ディスプレイ 24–28pt（主役式のみ最大32pt） |
| コード | Menlo / Consolas | 14–16pt |

#### 実務で踏みやすい3つの罠
1. **明朝体の使用**：「MS明朝」「游明朝」などはプロジェクター投影時に横線が細く痩せて読めなくなります。スライド本文は必ずゴシック体を使います（論文予稿とは逆）。MSゴシックも可読・見栄え両面で避けます。
2. **和文ウェイトの無指定**：「ヒラギノ」「游ゴシック」などを無指定（細字のまま）で見出しに使うと、会場後方から非常に見えにくくなります。見出しには必ず太字ウェイトを明示します。
3. **Mac / Windows 間のフォント化けと自動フォールバック**：
   - **macOS版 Microsoft PowerPoint の罠**：ファミリー名 `Hiragino Kaku Gothic ProN` をそのまま指定すると PDF 書き出しや環境によって解決できず、**無断で MSゴシック / Calibri に化ける**ことがあります。`Hiragino Sans`（＋bold）や `Hiragino Kaku Gothic ProN W3` / `W6` のようにウェイト付きで指定するか、クロスプラットフォーム配布では両OSにある書体（`Yu Gothic` / `Noto Sans JP` / `BIZ UDPGothic`）を選び、幅に約10%の余裕を持たせます。
   - **Aptos のデフォルト使用に注意**：新しい Office の標準フォント Aptos は古い Office や他環境で欠落しやすく、文字幅ズレの原因になるため共有デッキには使いません。
   - PowerPoint で `.pptx` からプログラム的に書体指定するときは、欧文（`a:latin`）だけでなく東アジア文字（`a:ea`）・複合文字（`a:cs`）の3属性を揃えて設定します。

### 2. サイズ下限と例外の厳格な分離
- 本文・表セルを含む通常テキストは **16pt を絶対的な下限（安全フロア）、18〜24pt を実用推奨** とします。
- 11〜14pt の小文字が許容されるのは **「ページ番号」「書誌出典（Source）」「純粋な補助ラベル」** だけです。**結果の解釈に必要な実験条件（N数、誤差棒の種類、パラメータ）を「脚注」扱いにして小文字で隠してはいけません。**

### 3. 改行・表記揺れ・ネイティブリスト
- **不自然な単語途中での改行を禁止**：テキストボックスの右端で `モデ/ル` `シミュ/レーション` や手法名が途切れないよう、文節の切れ目で手動改行するか、文字サイズを 1〜2pt 下げるか、ボックス幅を広げます。
- **1行タイトルのゆとり**：1行で収めたいタイトルが微妙に折り返す場合は、テキストボックスの幅に少し余裕（+0.125インチ相当など）を確保するか、文自体を短く削ります。
- **ボックスの横幅不足（3行以上の折り返し）**：狭いカラムに文章を入れて3行・4行に折り返されている状態はレイアウト破綻のサインです。ボックスを広げるか、文章を短くするか、レイアウトの型を変えます。
- **表記揺れの徹底排除**：「AIモデル」「ＡＩモデル」「AI モデル」のような全角/半角/スペースの揺れを最後に一括チェックします。
- **リストは必ずネイティブ機能を使う**：`"• "` や `"1. "`、丸数字、あるいは独立した番号図形を手打ちして擬似リストを作らないでください。後から人間が PowerPoint 上で項目を足し引きするときに編集できなくなります。

## 第2部：日本語「AI臭ワード・言い回し」排除集（AI Slop Lexicon）

スライド・メール・報告書に共通する「AIが量産した薄くてくどい文体」を消すための語彙・構文フィルターです。

### 0. 核となる原則
- **冗長。まず削る**（説明文やサマリーはまず400字目安まで圧縮できないか疑う）。
- **過剰に懇切丁寧＝「全部を言い換えるくどさ」を消す**。遠回しな前置きや装飾語を削り、直球で言い切る。
- **定型文・記号装飾に頼らない**。

### 1. 消すべき単語・言い回し

| カテゴリ | 避けるワード・表現 | 代わりに使う表現 |
|---|---|---|
| **空虚な強調** | まさに／いわば／非常に／極めて／大変／圧倒的に／画期的／革新的／次世代の／〜と言っても過言ではない／〜に他なりません | 具体的な数値・差分・事実（「従来比2.3倍」「待ち時間40%減」等） |
| **カタカナ盛り** | ソリューション／シナジー／シームレス／エンドツーエンド／コミット／ブラッシュアップ／バリュー／インサイト／付加価値 | 解決策／連携／切れ目なく／一貫して／見直し／価値／知見 |
| **名詞句化ビジネス語** | 最適化／効率化／活用／推進／加速／強化／担保／寄与／実現／創出／〜に資する | **素の動詞に戻す**（「活用して」→「使って」、「実現します」→「できます」、「向上に寄与する」→「〜を高める」） |
| **自己美化・スローガン** | 寄り添い／伴走し／二人三脚で／尽力してまいります／邁進／さらなる高みへ／〜な世界を目指します | 具体的な行動・提供内容だけを書く |
| **定型の枕詞** | 昨今／近年／変化の激しい時代／現代において／まず結論から申し上げますと／以下の通りです | 枕詞ごと削除し、いきなり本題・結論から入る |
| **過剰敬語・回りくどさ** | 〜させていただきます の乱用／〜いただけますと幸いです の連発／〜することが可能です／〜になります（こちらが資料になります） | 〜します／〜してください／〜できます／〜です |
| **抽象の水増し** | 〜という点において／〜の観点から／〜に関しまして／〜な側面／〜のフェーズ／重要なポイント／鍵となる／肝となる | 削る。主語と述語を直結させる |

### 2. 崩すべき構文・文法
- **機械的テンプレートの反復**：「ポイントは3つあります」「まず・次に・最後に」「結論→理由→まとめ」の毎回固定。
- **報告書調・過剰フォーマット**：何でも「太字見出し＋番号リスト＋絵文字アイコン」にする癖。
- **三点セット・対句の連打**：「〜し、〜し、〜する」「AだけでなくBも、さらにCも」や体言止め対句の多用。
- **接続詞過多**：文頭の「また／さらに／加えて／したがって／そのため／このように」は **8割削っても意味が通じる**。
- **一文が長く主語と述語が遠い／翻訳調**：受動態（「〜の改善が図られる」→「〜を改善する」）や不必要な主語の毎回明示をやめる。
- **断定回避の連発**：「〜と言えるでしょう」「〜と考えられます」の繰り返し。事実なら言い切り、推論なら根拠と範囲を明示する。
- **ダッシュ連結**：補足や言い換えを「 — 」で繋ぐ文体を多用しない。句点で文を切るか、「：」や括弧に置き換える。

### 3. トーン・情報設計の引き算
- **定型締め・空虚な相槌を消す**：「いかがでしたでしょうか」「ぜひご検討ください」「素晴らしいですね」「おっしゃる通りです」等の尻尾を切る。
- **揺れのなさ・綺麗すぎを疑う**：何でも MECE に無理やり割り切って全部盛りにすると、体温がなく薄い文章になります。
- **人間の良い書き方の基準**：
  - 短い／1文＝1行／要点だけ
  - 数字・日付・選択肢を具体に出す
  - 正直に言い切る（未確定や限界はごまかさず「未検証」「課題」と書く）

### 4. 仕上げ前の「30秒セルフチェック」
1. 削れる語（空虚な強調・接続詞・枕詞・定型締め）を消したか？
2. 絵文字・装飾記号・過剰な太字を撤去したか？
3. 名詞句の羅列（「〜の最適化の推進」）を素の動詞に直したか？
4. 声に出して読んで「自分が本当に口にする自然な言葉」になっているか？
5. スライドの本文が長すぎないか（口頭発表なら「箇条書きを半分以下」に削れないか）？
