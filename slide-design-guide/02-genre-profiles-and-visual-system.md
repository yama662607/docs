# 02. ジャンル別プロファイル＆視覚システム

[01-universal-principles.md](./01-universal-principles.md) が全資料共通の土台であるのに対し、本ドキュメントは **「用途（誰が何をするか）」と「消費モード（どう見る／読むか）」** によって変わる設計規範と、統一感のあるビジュアルシステムを定義します。

---

## 1. 最初に決める2つの軸（Universal Deck Fallacy の回避）

設計を始める前に、必ず次の2点を確認します。

1. **聴衆はこの資料で何をするか？**
   - 理解し検証する（学術） / 意思決定し行動する（ビジネス） / 学び定着させる（講義）
2. **どのように消費されるか？**
   - **ライブ発表（Presented）**：音声が説明を担うため、スライドは疎（スパース）に保つ。
   - **単独読解（Read standalone）**：発表者なしで完結させるため、論理と文脈を言語化し密度を上げる。

> **重要原則（Universal Deck Fallacy）**  
> 1つの資料で「ライブ発表用」と「配布・読む用」の両方を兼ねようとしてはいけません。必要な情報密度と文章量が真逆であり、兼用（いわゆる *slideument*）にすると両方の用途で機能不全を起こします。必要なら **発表用（疎）と送付・配布用（密）を分ける** か、発表者ノート／別添資料へ逃がします。

### プロファイル一覧

| プロファイル | 聴衆のモード | 消費形態 |
|---|---|---|
| `progress-meeting`（研究室進捗報告） | 議論・助言・方針決定 | ライブ発表・対話型 |
| `journal-club`（論文紹介） | 理解・批判的検討 | ライブ発表 |
| `conference-talk`（学会講演） | 関心喚起・論文への誘導 | ライブ発表（時間厳守） |
| `phd-defense`（博士論文審査） | 貢献と厳密性の審査 | 長時間ライブ＋試問 |
| `consulting-deck`（コンサル・意思決定資料） | 意思決定・承認 | **単独で読む** |
| `pitch`（投資家向けピッチ） | 投資判断 | ライブ（＋送付用Reading Deck） |
| `internal-proposal`（日本企業の社内稟議・提案） | 決裁・合意形成 | **単独で読む（回覧）**＋事前説明 |
| `dashboard-report`（KPI・データ報告） | 状態把握・打ち手判断 | 定点観測・意思決定 |
| `lecture`（講義・ワークショップ） | 理解・定着・ハンズオン | ライブ（＋黒板/配布物分離） |
| `poster`（学会ポスター A0/A1） | 立ち止まり→主張把握→対話 | **1〜2m距離で立つ＋著者対話** |
| （既存テンプレート準拠） | 任意 | **既存のデザイン体系を継承**（独自システムは適用しない） |

## 2. 作成前の「5行の品質計画（Quality Plan）」

ゼロからスライドを作るときは、レイアウトを組む前に以下5点を設計します。トピック名を入れ替えれば別の発表にも流用できるような一般論なら、書き直します。

1. **主張の背骨（Claim spine）**：1スライド1主張のタイトル列。タイトルだけ読んで全体のストーリーが通じるか。
2. **証明オブジェクト（Proof objects）**：各主張を裏付ける図・グラフ・数式・表・画像・動画。**文字だけの箇条書きは証明オブジェクトではない。**
3. **視覚的モチーフ（Visual motif）**：その題材から導かれた反復デザイン要素（例：位相図パネル、パラメータバッジ、数式と結果の対比枠、図のサイドレール）。単なる飾り帯や汎用アイコン行はモチーフにしない。
4. **配色の役割（Palette roles）**：ベース色・構造色・ハイライト色の3役とそれぞれの意味。無関係な営業資料にそのまま貼れてしまう配色なら選び直す。
5. **コンタクトシートのリズム（Contact-sheet rhythm）**：レイアウトの並び順。講義の段階導出など意図的な連続を除き、3枚続けて同じシルエットにしない。

## 3. ビジュアルシステム（ライブ発表系プロファイルの標準設計）

### サンドイッチ構造（Sandwich Structure）
- **表紙**（および必要に応じて締めのディスカッション用スライド）を濃い背景色（例：深紺 `#1B2A4A`）にし、**中身のコンテンツスライドは白背景** にします。
- サムネイル一覧（コンタクトシート）で見たときに、デッキ全体が意図された一つの構造として引き締まります。

### テーマに沿ったカラーロール
配色はできるだけ研究・業務の題材（顕微鏡画像、シミュレーションの配色、素材の質感、ブランド色など）から導きます。以下は汎用的な安全デフォルト例です。

| 役割 | デフォルト例 | 用途 |
|---|---|---|
| Ink（本文） | `#1A1A1A` | 白背景上の本文テキスト |
| Paper（背景） | `#FFFFFF` | コンテンツスライドの背景 |
| Deep accent（構造色） | `#1B2A4A`（深紺） | 濃色カバー、主張の強調、フィット曲線 |
| Highlight（強調色） | `#D55E00`（朱色） | **主役となる1つの数値・語句・データ点** |
| Muted（補助） | `#666666` | キッカー、出典、ページ番号、条件注記 |

- 色数は **3〜4色以内** に抑え、1色＝1意味を貫きます。
- 明るいオレンジ・アンバー系は小さな文字やカバー上で浮きやすいため、実際の見た目を確認した上で使います。

### カバー（表紙）の構成
- 空白の中央にタイトルだけポンと置かず、**2〜3のアンカー領域** で画面を構成します（例：上端や下端に日付・会議名、視覚的中心のやや上にメインタイトル、反対側の端に所属や1行の文脈）。
- タイトルが短いときはフォントを拡大するか意味のある文脈を補い、画面中央に不自然な大空白を作らないようにします。
- 濃色カバーでは、強調色はタイトル全体ではなく**短いキーフレーズや最重要指標1箇所だけ**に使います。

### タイトル帯（Title Band）とキッカー（Kicker）
- コンテンツスライドのタイトルは **上端から約 0.3〜0.5インチ** の同じ高さに固定します（垂直中央寄せは表紙・中扉専用）。
- タイトルの直上に、そのスライドの役割を示す小さなミュート色のラベル（**キッカー**：例 `結果 2/3`, `議論`, `NEXT`, 11–12pt）を置くと、聴衆が現在地を把握しやすくなります。
- **1行タイトルをデフォルト**とします。長すぎる場合は「まず削る → 1〜2pt下げる → 短いタイトル＋補助サブラインに分ける」の順に調整し、2行にするなら本文エリアを下へずらして十分な余白を保ちます。

### レイアウトファミリーとリズム
1つのデッキ内で以下のシルエットを組み合わせ、視覚的なリズムを作ります（**2枚連続までは同じ型でも可、3枚連続は禁止**）。
- **Claim + Figure**（主力：上部に主張、下に大きな図）
- **Figure + Side-rail**（左に大きな図やデータ、右に解釈・So What）
- **Stat Callout**（主役の数値1つを大きく提示＋単位＋1行の文脈）
- **Two-column Compare**（2対象・Before/Afterの比較）
- **Timeline / Steps**（プロセスやネクストアクション）
- **Discussion Card**（静かな淡色パネルで論点や意思決定事項を整理）

> **Stat Callout の規律**：60pt 級の巨大数字は「このデッキ／スライド最大の結論となる1つの数値」＋「単位」＋「文脈（例：`緩和時間の極小（ρ ≈ 0.54）`）」にのみ使います。重要でない数字を大きくするのは単なる装飾です。

## 4. ジャンル別プロファイルの詳細規範

### A. 学術系プロファイル（共通コア規範）
- **Research Question を冒頭に出す**：遅くとも2〜3枚目で中心となる謎・問いを提示し、一般論の背景説明に埋もれさせない。
- **物語の背骨**：SCR（Situation / Complication / Resolution）または漏斗型（Funnel：広い背景→具体的ギャップ→本研究の問い）を使う。
- **1枚1図（One exhibit per slide）**：各コンテンツスライドには主張を直接証明する図表を1つ置く。
- **語数の上限**：ライブ発表は1枚あたり約40語目安。箇条書きは話す原稿ではなく方向指示（orientation cues）。

#### 1. `progress-meeting`（研究室進捗報告 / 5〜10枚）
- **目的は「スライドの完成」ではなく「議論を引き出すこと」**。学会発表のように完璧に磨き込みすぎると「結論はすでに固まっている」と受け取られ、助言や突っ込みが出にくくなります（あえて余白と未解決点を残す）。
- 構成例：
  1. **表紙**：テーマ、日付、1行の文脈
  2. **前回まで（Recap）**：前回の到達点と今週の問い
  3. **結果（結果 n/m）**：主張タイトル＋図/動画＋小文字の条件行（N、パラメータ、データセット）
     - 動画や並列比較では、パネルを同じサイズ・同じベースラインに揃え、単なる値ラベルだけでなく比較軸（`低密度` / `高密度`, `control` / `perturbation`）と「どこを見てほしいか」の1行を添える
  4. **解釈・問題点**：具体的な現象（例：「ρ>1.1でフィットが発散」）と、**まさに今日決めてほしいこと／助言が欲しいこと**をまとめた議論カード
  5. **ネクストステップ**：2〜4項目（期待される結果、判断基準、優先度・期限）
  6. **Appendix**：詳細パラメータや補助プロット（Appendix へ移せるのは失敗ではなく整理の成功）

#### 2. `journal-club`（論文紹介）
- 聴衆はその論文を読んでいません。守るべき2つの鉄則：
  1. **どの図も、解釈に入る前に「軸・単位・凡例」を説明してから本題に入る。**
  2. **「著者の主張（論文のDiscussion）」と「自分の評価・批判」を明確に分ける。**（発表者は論文内容の責任者ではないため、批判的視点は色やレイアウト枠を変えて自分の声として提示する）。
- 査読済み論文かプレプリント（arXiv等）かを明記する。引用図は再描画しても「From … / Adapted from …」の出典表示を省略しない。

#### 3. `conference-talk`（学会講演 / 一般10–15分、招待30–45分）
- Simon Peyton Jones の原則：**「論文は牛肉そのもの、講演はその広告」**。証明や細部を全部語ろうとせず、**「これだけは覚えて帰ってほしい」という1つの核心**に削ぎ落とす。
- スライド枚数は持ち時間（分）より少なめにし、息継ぎと質疑の余白を残す。
- 冒頭1〜2枚で問題と重要性を示し、**主な結論を序盤で先出し**する（ミステリー小説のように最後まで隠さない）。
- **聴衆は3枚目の内容を9枚目で覚えていません**。必要なら「さっきの図」と参照するだけでなく、ミニ図や値を再掲します。
- 先行研究（Related Work）は単なる年代順リストではなく、**自分の主張に関係する比較軸**で整理します。

#### 4. `phd-defense`（博士論文審査 / 45〜90分）
- 学位論文の章立てをそのままなぞらず、**Swath and Dive パターン**を推奨：
  - **Swath（約50%）**：研究全体の俯瞰（冒頭で自分の具体的貢献を明示）
  - **Dive（約30%）**：1〜2個の最重要知見を生データ・数理まで深掘り
  - **Coda（約20%）**：限界と今後の展望
- 共著研究でも `"we"` を連発して自分の貢献を曖昧にしない。

### B. ビジネス系プロファイル

#### 1. `consulting-deck`（意思決定用・単独で読む資料）
- BCG の標榜する「**プレゼンターを必要としないほど明快な資料**」を目指す。
- **アクションタイトル（So-What タイトル）**：トピック名ではなく「結論＋定量的インパクト＋主因」を1文で書く（英語なら15語以内、日本語なら40字前後）。タイトルに「および／and」が入りそうならスライドを分割する。
- **水平フロー（Horizontal Flow）**：タイトルだけを1枚目から順番に読んだときに、論理が完全に繋がる状態にする。
- **ピラミッド原則（Barbara Minto）＆ MECE**：結論を頂点（先頭）に置き、同階層の根拠を漏れなくダブりなく（MECE）並べる。導入には **SCQA / SCR**（状況→複雑化/課題→問い→解決策）を使う。
- **エグゼクティブサマリー（BLUF: Bottom Line Up Front）**：冒頭1枚（300–500語）で結論を出し、太字の結論＋インデントされた裏付け箇条書きで、経営層は太字だけ30秒で追える構造にする。
- **出典徹底とAppendix設計**：すべての数値に `"Source: ...; 年月"` を明記。Appendix は「余り物」ではなく「想定質問に15秒で答えるための準備済み回答集」。
- 読む用資料は情報密度が高くなりますが、**「領域のグルーピング」と「視線の入口1つ」** を保って整理すれば散らかりません。

#### 2. `pitch`（投資家向けピッチ）
- **Guy Kawasaki の 10/20/30 ルール**：約10枚・20分以内・30pt以上（残り時間を質疑・議論に使う）。
- **ストーリーアーク**：問題 → 解決策 / Why Now → 市場規模（トップダウンの兆円×1%だけでなく、顧客単価×現実的顧客数のボトムアップ TAM/SAM/SOM） → トラクション（絶対数より伸び率） → チーム / 参入障壁（moat） → Ask。
- 成長曲線（ホッケースティック）を出すなら**変曲点の理由**を必ず説明する。
- **発表用（疎）と送付用 Reading Deck（密）の2つを必ず分ける。**

#### 3. `internal-proposal`（日本企業の社内報告・稟議・提案）
- 作成者不在で回覧されるため、**「一人歩きする資料」の4要素**（タイトル表紙・1枚サマリー結論・目次と現在地・期待するアクションの明記）を備える。
- トヨタの **A3一枚思考** に倣い、「1画面で全体像が把握できる構造化」と、**「見せる投影資料」と「読ませる配布資料」の明確な分離**を行う。文字が小さすぎる・3Dグラフ・過剰装飾の「昭和的過剰品質」を避ける。

#### 4. `dashboard-report`（KPI・データ報告）
- **One Chart, One Claim**：多数タイルのダッシュボード画面をそのまま貼らず、「見出しで結論を1文で述べる → 証明する単一チャート（または大きな数値）を置く → 意思決定への示唆（So What）で締める」。一文で言えないなら再構成する。
- KPI は **3〜5個** に絞り、意思決定に影響しない不要な小数点（False precision）は丸める。
- ステータス表現（RAG：赤・黄・緑）は報告者の「緑にしておこう」バイアスと色覚異常リスクがあるため、**矢印・シンボル・基準値**を併用する。

### C. 講義・ハンズオン系プロファイル（`lecture`）
- **逐次開示（ビルド）の適切な使用**：導出や段階的図解では「言及時に表示し、話し終えたら薄くする」逐次開示が教育心理学的に有効。一方、自由な質問や脱線を促したい場面では静的なスライドにする。
- **黒板・ホワイトボードとの分担**：完成された図・定義・データ＝スライド、段階的な式変形やその場のペースダウン＝板書・手書き、と役割を分ける。
- **「スライド」と「ハンドアウト（教材）」を分離**：講義スライドに解説文を詰め込むと、読むことと聞くことが競合しノートテイキングの効果も下がります。解説は発表者ノートまたは別配布資料へ分けます。
- **コード・ハンズオン提示**：コードは1画面 **10〜15行以内**、投影環境では **黒背景より白背景（高コントラスト）** が後ろの席から読みやすく安全。ライブデモの失敗リスクを避けたい場合は整形済みコードやステップ番号・現在地表示（目次）を明確にします。
